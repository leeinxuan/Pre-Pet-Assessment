# 新物種程式實作準則

> 目的：將一份 `{species}-game-planning.md` 轉為本專案可維護的資料與流程。企劃是內容唯一來源；本文件只定義程式資料應放在哪裡、如何連接既有流程，以及如何避免破壞其他物種。

---

## 壹、先確認的原則

1. **企劃決定內容，程式決定呈現。** 題目、選項、費用、說明、重點字、回饋與報告摘要都只能從目標物種的 planning md 帶入。既有物種只能作為欄位與互動方式的參考，不能複製後改物種名稱。
2. **物種差異放資料；共用元件只渲染。** 不要在 `app/page.tsx`、`LifeJourneyComponents.tsx` 或報告元件內硬寫新物種文案與費用。
3. **資料存在不等於費用已發生。** 每筆費用需要穩定 ID、資料來源與明確觸發事件；未觸發前不可預先出現在明細、預估總額或匯出內容。
4. **素材路徑必須先驗證。** 先以 `rg --files public/assets` 查到實體檔案，再使用 `/assets/...` 公開路徑。沒有素材時使用既有中性佔位，不建立猜測的路徑。
5. **先讓通用流程可走，再擴充新玩法。** 新玩法只有在現有 `Scenario`、`JourneyItem.type`、房間／出發前準備元件無法表達時才新增。

## 參、現行資料責任

### 3.1 物種資料夾

每個已開放物種以 `app/data/species/{species}/` 為主要資料邊界。實際檔案可依玩法需要增減，不要求為了「目錄完整」建立空檔案。

```txt
app/data/species/{species}/
├── index.ts          # 唯一組裝入口
├── assets.ts         # 已驗證的素材公開路徑常數
├── preparation.ts    # 房間用品、危險物、出發前用品
├── feeding.ts        # 第一餐物品欄尺寸、場景內素材的桌機／手機位置
├── layout.ts         # 位置與響應式座標（需要時）
├── journey.ts        # JourneyItem 順序、活動設定
├── scenarios.ts      # 題目、選項、完成回饋
├── expenses.ts       # 該物種唯一的費用名稱、金額、分類與說明
├── report.ts         # 報告與 PDF 使用的物種資料
└── {activity}.ts     # 只有專屬互動需要時才建立
```

選擇資料可以放在 `selection.ts`，也可以像兔子、鸚鵡一樣放在物種 `index.ts`；重點是由該物種組裝入口輸出，不是檔名本身。

### 3.2 註冊入口

新增可遊玩物種時，至少檢查：

1. `app/data/shared/types.ts` 的 `SpeciesId`。
2. `app/data/speciesGameConfig.ts` 的 `speciesGameConfig` 與對應型別／fallback。
3. `app/data/species/index.ts` 的 `speciesConfigs` 與 `getSpeciesConfig`。
4. `app/data/shared/expenses.ts` 的 `expenseCatalogBySpecies`。
5. `app/page.tsx` 是否已能從 `getSpeciesConfig(category)` 取到新設定，以及重置流程是否會清掉新物種 state。

`app/data/species/species-config.ts` 是目前保留的相容／過渡設定層；**不要因為新增物種就盲目複製註冊**。只有實際 import 鏈仍使用它時才同步更新，並在變更前以 `rg` 確認呼叫端。

### 3.3 企劃內容的落點

| planning 內容 | 主要資料位置 | 共用畫面 |
| --- | --- | --- |
| 物種顯示名稱、預設名字、是否跳過品種頁、過往經驗文案 | 物種 `index.ts`／selection 資料、必要時 `speciesGameConfig.ts` 的 copy | 選擇、命名、過往經驗、新的開始 |
| 家庭與居住確認 | `app/data/shared/home-readiness.ts` | `HomeReadinessActivity` |
| 危險物、房間用品、出發前用品 | `{species}/preparation.ts`、`assets.ts`、必要時 `layout.ts` | `RoomPreparation`、`CarTrunkPreparation` |
| 第一餐物品欄圖片尺寸；場景內角色、食碗、水碗與蔬菜的位置／尺寸 | `{species}/feeding.ts` | `ArrivalMealActivity` |
| 題目、選項、完成回饋、小知識、重點字 | `{species}/scenarios.ts` | `LifeJourney` 與共用完成頁 |
| 題目／互動的順序與活動類型 | `{species}/journey.ts` | `LifeJourney` |
| 特殊互動的熱區、步驟、素材切換 | `{species}/{activity}.ts` 或既有設定檔 | 對應共用互動元件 |
| 已建立觀念、額外提醒、PDF 摘要、照護時間 | `{species}/report.ts` 與必要的 `app/data/shared/*` 映射 | `AssessmentReport`、PDF／PNG |

## 肆、費用資料與觸發

### 4.1 物種費用檔

所有金額與費用說明只放在 `{species}/expenses.ts`：

```ts
import type { ExpenseRecord } from "../../../game-types";

export const newSpeciesExpenses: Record<string, ExpenseRecord> = {
  "new-species-carrier": {
    id: "new-species-carrier",
    name: "企劃中的費用名稱",
    amount: 0, // 範例，正式資料不可保留 0 或 placeholder
    category: "一次性準備費",
    stage: "出發前準備",
    recurring: false,
    description: "企劃費用清單中的說明",
  },
};
```

`app/data/shared/expenses.ts` 只做以下事情：

- 匯入各物種 `expenses.ts`，建立 `expenseCatalogBySpecies`。
- 提供舊元件相容使用的合併 `expenseCatalog`。
- 提供 `getExpenseForSpecies`、金額格式、犬隻尺寸調整與臨時預留判斷。

不可把新物種金額重新寫回共用檔，也不可讓 UI 依費用名稱決定說明或金額。

### 4.2 ID 與同名費用

1. 新增 ID 使用英文小寫 kebab-case，通常採 `{species}-{purpose}`，例如 `rabbit-air-conditioning`。
2. 只有名稱、金額、分類、說明與觸發語意都完全相同時才重用 ID。
3. 同一 ID 必須一致出現在費用檔 key、`ExpenseRecord.id`、`RoomItem.expenseId(s)`、`TrunkItem.expenseIds`、`JourneyItem.expenseIds` 與情境選項的 `expenseIds`。
4. 犬貓目前有少數相同 ID、不同說明的歷史相容資料；新增資料應優先使用物種前綴，避免合併目錄覆蓋。

### 4.3 出發前物品欄的圖片 class

`TrunkItem.id` 是互動、完成狀態與費用關聯使用的穩定識別，不得為了調整圖片尺寸而改名。需要跨物種共用圖片尺寸規則時，使用 `TrunkItem.visualClassName`；`CarTrunkPreparation` 會產生 `departure-item-image--{visualClassName}` class。

- 身分證統一設定 `visualClassName: "id"`；領養／交接文件統一設定 `visualClassName: "documents"`。
- CSS 只保留實際有資料使用的共用 selector，例如 `.departure-item-image--id`、`.departure-item-image--documents`；不要為舊互動 ID 再保留別名 selector。
- 若物品沒有共用尺寸需求，不填 `visualClassName`，元件會以穩定 `id` 作為 class key。
- 各物種的外出籠／運輸箱圖片大小使用該物種 `preparation.ts` 中 `TrunkItem.visualScale` 調整；不可再用共用 `.departure-item-image--carrier` 覆寫所有物種。此欄位只影響物品欄圖片，不影響放入後車廂的 `placement` 尺寸。

### 4.4 第一餐的尺寸與場景位置

`ArrivalMealActivity` 是共用元件；各物種不可再以 CSS selector 或犬隻座標覆寫畫面。

- 第一餐**物品欄**圖片的桌機／手機尺寸放在各物種 `feeding.ts` 的 `arrivalMealSupplyImageSizes`。
- 第一餐**場景內**角色、食碗、水碗與蔬菜的桌機／手機 `left`、`bottom`、`width`、`maxHeight` 放在各物種 `feeding.ts` 的 `ArrivalMealSceneLayout`。
- `feeding.ts` 只管理位置與尺寸；素材、食物規則、完成條件與費用仍由各物種既有資料設定管理。

### 4.5 觸發時機

| 類型 | 設定位置 | 寫入時機 |
| --- | --- | --- |
| 房間用品 | `RoomItem.expenseId`／`expenseIds` | 成功放入房間時 |
| 出發前用品 | `TrunkItem.expenseIds` | 玩家完成該用品操作時 |
| 已買過的重複用品 | `TrunkItem.reusedExpenseIds` | 顯示為已計入，但不得再次加錢或重播動畫 |
| 到家後必要支出 | `JourneyItem.expenseIds` 或企劃指定情境資料 | 指定題目進入成功回饋後 |
| 生病／高齡等臨時預留 | 正確選項或完成事件的 `expenseIds` | 對應題目成功回饋後；未觸發前不顯示 |

不要以載入頁面、開啟報告或查看 PDF 當作費用觸發。所有畫面、報告與匯出都應讀同一份已觸發 expense store。

## 伍、題目、完成頁與重點字

### 5.1 資料驅動題目

題目放在 `{species}/scenarios.ts`，順序放在 `{species}/journey.ts`。共用元件不能依物種名稱切換文字：

```ts
{
  id: "new-species-arrival",
  stage: "接回家",
  title: "第一天適應新家",
  description: "企劃情境文字",
  questionText: "企劃問題文字",
  choices: [/* 企劃選項與結果 */],
  completionFeedback: {
    title: "做得很好！",
    encouragement: "企劃鼓勵文字",
    knowledgeTitle: "企劃小知識標題",
    knowledgeContent: [{ type: "paragraph", text: "企劃小知識" }],
  },
}
```

若企劃要求新的互動機制，先判斷是否可以用現有資料欄位處理；只有不能時才：

1. 擴充 `app/game-types.ts`。
2. 擴充 `initialLifeActivityState`、重播與完整重置行為。
3. 在 `LifeJourney` 新增明確的 `JourneyItem.type` 渲染分支。
4. 讓熱區、題目文字、選項、素材路徑與完成回饋都由物種資料供應。

### 5.2 變數與重點字

- 保留 `{petName}`、`{oldPetName}` 等變數，透過既有 `withPetName`／插值流程顯示；資料檔不可寫死示範名字。
- planning md 的 `**重點字**` 在資料中保留標記，並經既有 rich-text renderer 呈現為網站既有重點色與字重。
- 不可使用 `dangerouslySetInnerHTML`，不可讓使用者看到 `**`、`__`、`<mark>`。
- 非重點文字維持一般樣式；不得用整段上色取代精準標記。

### 5.3 缺資料與 TODO

企劃缺少必要內容或素材時，不編造照護建議、選項或圖片。可在程式附近留下可搜尋的註記：

```ts
// TODO(species:new-species, section:§5.3.2, type:asset, status:blocked):
// 企劃指定素材尚未提供；畫面使用既有中性佔位，待提供正式素材後替換。
```

TODO 不可顯示給玩家，也不可當作提交 placeholder 文案、假圖片或虛構費用的理由。

## 陸、素材與互動可及性

1. 路徑在資料檔前先由 `rg --files public/assets` 驗證。
2. `public/assets/foo.png` 的 UI 路徑為 `/assets/foo.png`。
3. 不可用其他物種的主角、器官、疾病或棲地素材代表新物種；通用用品也只能在不造成物種誤導時重用。
4. 缺圖使用既有 `.scene-media-placeholder` 或 `.preparation-asset-placeholder`，不要建立 404 `src`。
5. 新增互動要支援滑鼠、觸控與鍵盤，提供可讀的 `aria-label`；對話框和長內容不可被父層 `overflow: hidden` 裁切。
6. 動畫需要提供 `prefers-reduced-motion` 的靜態或淡入替代，不可讓減少動態時資訊順序消失。

## 柒、建議實作順序

1. 從 planning md 列出「選擇／準備／旅程／費用／報告／素材」對照表與完成條件。
2. 驗證素材，列出缺件；缺件先決定中性佔位，不猜檔名。
3. 建立物種資料模組與 `index.ts` 組裝入口。
4. 註冊物種設定、費用目錄與選擇入口，確認切換與完整重置不殘留前一物種資料。
5. 實作家庭與居住確認、房間與出發前準備；確認鎖定規則、位置與費用只加一次。
6. 實作 `Scenario` 與 `JourneyItem`，先測試資料題，再做專屬互動。
7. 將費用 ID 接到用品與題目，逐項確認動畫、明細、總額、報告及 PDF／PNG 一致。
8. 補齊報告、照顧路上提醒與官方資訊，並設定「只在完成活動後顯示」的條件。
9. 做跨物種、桌機、手機、重新整理、重播與完整重置驗證。

## 捌、交付前驗收

### 資料與流程

- [ ] 新物種只在物種資料與必要共用型別中新增內容；沒有散落於 UI 的物種文案或金額。

- [ ] 每個 journey item 都有正確順序、完成條件、重播與完整重置行為。
- [ ] 尚未完成的活動不會在「你已建立的照顧觀念」中偽裝成完成。

- [ ] 所有可見文字、重點字、費用名稱／說明都逐字來自目標 planning md。

## 玖、禁止事項

| 禁止 | 正確做法 |
| --- | --- |
| 從既有動物文案改名稱後當成新資料 | 只以目標 planning md 填寫內容。 |
| 在 `page.tsx` 或共用元件寫新物種長文案／金額 | 放進物種資料檔，由共用元件讀取。 |
| 在未完成題目前預先加入臨時或高齡費用 | 只在對應成功回饋後，依費用 ID 寫入。 |
| 只更新畫面金額而未更新費用資料 | 修改 `{species}/expenses.ts`，讓所有畫面與匯出同步。 |
| 依名稱、陣列位置或文案判斷費用與答案 | 使用穩定 ID 與資料欄位。 |
| 猜測素材路徑、用其他物種主角充數 | 驗證實體素材；缺件則使用中性佔位。 |
| 為文案差異複製一整頁／一整個完成頁元件 | 擴充資料型別與共用渲染能力。 |
| 未驗證就宣稱 lint、typecheck、build 全數通過 | 實際執行並如實回報結果。 |
